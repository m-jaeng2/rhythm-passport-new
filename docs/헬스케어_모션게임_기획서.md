# 헬스케어 모션 게임 기획서

## 1. 프로젝트 개요

### 1.1 프로젝트명
- 리듬 패스포트 (가칭)

### 1.2 프로젝트 목적
- 움직임이 불편한 노인과 장애인이 앉은 자세에서도 즐겁게 참여할 수 있는 헬스케어 운동 프로그램을 제공한다.
- MediaPipe 기반 자세 및 동작 인식을 활용해 웹 게임에서 실시간 운동 피드백을 제공한다.
- 동일한 동작 인식 결과를 Unity 앱과 연동해 확장형 재활 및 운동 콘텐츠로 발전시킨다.

### 1.3 핵심 가치
- 접근성: 서서 하지 않아도 되는 앉은 자세 중심 운동
- 재미 요소: 운동을 게임화해 반복 참여를 유도
- 확장성: 웹 게임과 Unity 앱이 같은 동작 데이터를 활용
- 실용성: 재활, 실버케어, 복지기관, 가정 운동에 적용 가능

## 2. 문제 정의

### 2.1 대상 사용자의 문제
- 고령자와 장애인은 일반 피트니스 콘텐츠를 따라 하기 어렵다.
- 복잡한 조작 없이도 참여할 수 있는 운동형 콘텐츠가 부족하다.
- 재활이나 가벼운 운동은 꾸준함이 중요한데, 반복 동기가 쉽게 떨어진다.

### 2.2 해결 방향
- 카메라만으로 상체 중심 움직임을 인식한다.
- 앉은 상태에서 수행 가능한 간단한 동작으로 구성한다.
- 동작 성공 여부를 즉시 시각화해 성취감을 준다.
- 단계별 난이도와 기록 기능으로 지속 사용을 유도한다.

## 3. 목표 사용자

### 3.1 주요 타깃
- 실내에서 가벼운 운동이 필요한 노인
- 보행이나 균형 유지에 어려움이 있는 사용자
- 장애로 인해 전신 운동보다 상체 중심 운동이 필요한 사용자

### 3.2 보조 타깃
- 복지관, 요양기관, 재활센터 운영자
- 보호자 및 가족
- 헬스케어/재활 콘텐츠 운영 기관

## 4. 제품 구성

### 4.1 웹 게임
- 브라우저에서 실행되는 MediaPipe 기반 모션 인식 게임
- 웹캠 입력을 통해 상체 및 팔 동작을 실시간 분석
- 앉은 자세에서 가능한 운동 동작을 게임 규칙과 연결

### 4.2 Unity 앱
- MediaPipe에서 인식된 결과를 WebSocket으로 전달받아 동작하는 앱
- 웹 게임과 별도로 더 풍부한 인터랙션과 시각 효과 제공
- 향후 키오스크, 태블릿, PC 앱 형태로 확장 가능

### 4.3 공통 동작 데이터 계층
- 포즈 좌표, 제스처 결과, 운동 성공 판정, 점수 이벤트를 공통 포맷으로 관리
- 웹과 Unity가 같은 이벤트 구조를 사용하도록 표준화

## 5. 서비스 목표

### 5.1 단기 목표
- 앉은 자세 기반 미니 운동 게임 1종 이상 구현
- 웹캠 기반 자세 인식 안정화
- Unity와 WebSocket 연동 프로토타입 구현

### 5.2 중기 목표
- 운동 콘텐츠 3종 이상 확장
- 사용자 점수/운동량 기록 기능 추가
- 난이도 조절 및 세션별 리포트 제공

### 5.3 장기 목표
- 재활 보조 콘텐츠 플랫폼화
- 기관용 관리 페이지 확장
- 운동 처방형 콘텐츠 및 AI 코칭 기능 검토

## 6. 핵심 시나리오

### 6.1 웹 게임 이용 흐름
1. 사용자가 웹 페이지에 접속한다.
2. 카메라 권한을 허용한다.
3. 화면 가이드에 따라 앉은 자세를 맞춘다.
4. MediaPipe가 사용자의 상체 및 팔 움직임을 인식한다.
5. 게임이 특정 동작을 제시한다.
6. 사용자가 동작을 수행하면 성공 여부와 점수가 반영된다.
7. 운동 종료 후 결과 요약을 확인한다.

### 6.2 Unity 연동 흐름
1. MediaPipe 기반 인식 모듈이 동작 데이터를 생성한다.
2. WebSocket 서버 또는 브리지 모듈이 데이터를 송신한다.
3. Unity 앱이 실시간으로 이벤트를 수신한다.
4. Unity 내 캐릭터, UI, 점수 시스템이 수신 결과에 반응한다.
5. 세션 종료 후 결과를 저장하거나 후속 콘텐츠로 연결한다.

## 8. 콘텐츠 방향

### 8.1 운동 설계 원칙
- 앉아서 안전하게 수행 가능해야 한다.
- 짧고 명확한 동작으로 구성해야 한다.
- 성공 판정 기준이 너무 엄격하지 않아야 한다.
- 반복에 대한 피로감을 줄이기 위해 게임적 보상을 제공해야 한다.

### 8.2 예시 콘텐츠
- 풍선 터뜨리기: 팔을 특정 방향으로 뻗어 풍선을 터뜨리는 게임
- 리듬 따라하기: 박자에 맞춰 양팔을 올리고 내리는 게임
- 목표 맞추기: 화면 목표물 방향으로 몸 또는 팔을 움직이는 게임
- 재활 미션: 지정 횟수만큼 좌우 회전 또는 팔 뻗기 수행

## 10. WebSocket 연동 설계 초안

### 10.1 메시지 구조 예시
```json
{
  "type": "motion_result",
  "userId": "guest-001",
  "timestamp": 1785148800000,
  "motion": "raise_both_hands",
  "score": 100,
  "success": true,
  "confidence": 0.92,
  "pose": {
    "leftShoulder": { "x": 0.42, "y": 0.31 },
    "rightShoulder": { "x": 0.57, "y": 0.30 }
  }
}
```

### 10.2 메시지 타입 예시
- `session_start`: 운동 세션 시작
- `pose_update`: 실시간 좌표 갱신
- `motion_result`: 특정 동작 판정 결과
- `score_update`: 점수 반영
- `session_end`: 세션 종료

### 10.3 설계 포인트
- Unity와 웹이 동일한 메시지 규격을 사용하도록 정의한다.
- 좌표 원본과 판정 결과를 분리해 필요한 수준만 전달한다.
- 지연 시간 최소화를 위해 가벼운 메시지 구조를 유지한다.

### 10.4 판정 구조 권장안
- MVP 단계에서는 웹에서 동작 판정을 완료한 뒤 Unity에는 결과 이벤트 중심으로 전달한다.
- Unity에는 `success`, `score`, `motion`, `progress` 같은 경량 이벤트를 우선 전달한다.
- 원시 랜드마크 전체 전송은 디버깅 또는 고급 모드에서만 제한적으로 사용한다.
- 웹과 Unity의 책임 범위를 분리해 중복 로직을 최소화한다.

## 11. UX/UI 방향

### 11.1 사용자 경험 원칙
- 첫 실행 시 카메라 설정이 쉬워야 한다.
- 큰 글씨와 높은 대비로 가독성을 높인다.
- 음성 또는 시각 가이드를 함께 제공한다.
- 피드백은 즉시, 명확하게, 긍정적으로 제공한다.

### 11.2 화면 구성 예시
- 시작 화면: 서비스 소개, 시작 버튼
- 카메라 세팅 화면: 자세 맞춤 가이드, 인식 상태 표시
- 게임 화면: 목표 동작, 점수, 남은 시간, 성공 효과
- 결과 화면: 운동 시간, 성공 횟수, 추천 메시지

## 12. 접근성 및 안전성 고려사항

### 12.1 접근성
- 색약 사용자를 고려한 색상 대비
- 큰 버튼과 단순한 화면 구조
- 텍스트와 아이콘의 중복 안내
- 반복 설명이 가능한 튜토리얼 제공

### 12.2 안전성
- 무리한 관절 가동 범위를 요구하지 않는다.
- 사용 중 통증 발생 시 즉시 중단 안내를 제공한다.
- 보호자 또는 운영자 동반 사용 환경을 고려한다.
- 의료기기 수준의 치료 효과를 직접 표방하지 않는다.

### 12.3 좌식 플레이 기준
- 일반 의자 또는 휠체어에서 상반신이 안정적으로 보이도록 카메라 높이 가이드를 제공한다.
- 상체 중심이 화면 중앙에 위치하도록 초기 위치 맞춤 단계를 둔다.
- 팔, 어깨, 머리 랜드마크가 일정 비율 이상 보일 때만 게임을 시작한다.
- 장시간 플레이를 방지하기 위해 1회 세션 시간을 짧게 설계한다.

### 12.4 중단 조건 예시
- 통증, 어지러움, 과호흡 등 이상 반응이 있는 경우 즉시 종료
- 카메라 인식이 지속적으로 실패해 잘못된 동작을 유도할 가능성이 있는 경우 종료
- 보호자 또는 운영자가 중단을 요청한 경우 즉시 종료

## 13. 개인정보 및 영상 처리 정책 초안

### 13.1 기본 원칙
- 카메라 영상은 가능한 한 로컬에서 처리한다.
- 서버에는 원본 영상 대신 최소한의 판정 데이터만 전송한다.
- 저장이 필요한 경우에도 사전 동의와 명확한 보관 목적을 제시한다.

### 13.2 데이터 최소화 방향
- 기본 전송 데이터는 동작 이름, 성공 여부, 점수, 타임스탬프 수준으로 제한한다.
- 좌표 데이터는 디버깅 또는 품질 개선 목적이 있을 때만 선택적으로 수집한다.
- 민감정보로 해석될 수 있는 영상 데이터는 기본 미저장을 원칙으로 한다.

### 13.3 운영 유의사항
- 서비스 초기 화면에 카메라 사용 목적을 명시한다.
- 영상 저장 여부와 보관 기간을 별도 정책으로 고지한다.
- 기관 도입 시 관리자 권한 범위와 열람 정책을 분리한다.

## 15. 주요 리스크 및 대응

### 15.1 기술 리스크
- 조명, 카메라 위치, 배경에 따라 인식 정확도가 흔들릴 수 있다.
- 저사양 기기에서 MediaPipe 성능 저하가 발생할 수 있다.
- WebSocket 지연 또는 연결 끊김이 게임 경험을 떨어뜨릴 수 있다.

### 15.2 사용자 리스크
- 사용자별 신체 조건 차이로 동일 판정 기준 적용이 어렵다.
- 장시간 사용 시 피로도가 높아질 수 있다.
- 초기 카메라 세팅 실패가 이탈로 이어질 수 있다.

### 15.3 대응 방향
- 자세 보정 가이드와 인식 범위 안내를 제공한다.
- 난이도와 판정 임계값을 조절 가능하게 설계한다.
- 로컬 모드와 연동 모드를 분리해 장애 시 대체 동작이 가능하게 한다.

## 16. QA 및 검증 계획

### 16.1 기능 검증
- 앉은 자세 기준으로 각 동작이 안정적으로 인식되는지 확인한다.
- 카메라 권한 허용부터 게임 종료까지 전체 흐름을 반복 테스트한다.
- WebSocket 연결 해제, 재연결, 지연 상황을 시뮬레이션한다.

### 16.2 사용자 검증
- 고령자 또는 보조 사용 환경에서 실제 사용성 테스트를 진행한다.
- 글자 크기, 색상 대비, 안내 문구 이해도를 확인한다.
- 피로도와 몰입도에 대한 정성 피드백을 수집한다.

### 16.3 기술 검증
- 브라우저별 성능 차이를 측정한다.
- Unity 수신 이벤트와 실제 화면 반응의 지연을 측정한다.
- 동작별 오인식 빈도와 재시도율을 기록한다.
