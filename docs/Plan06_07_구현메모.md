# Plan 06~07 구현 메모

## Plan 06. UI, 결과, 접근성

### 반영 내용
- 큰 글씨와 고대비 패널 유지
- 입력 소스 상태를 Title, Calibration, Gameplay 화면에 노출
- 세션 진행도와 목표 제한 시간을 진행 바로 표시
- Result 화면에 점수, 성공/실패 횟수, 플레이 시간 표시
- 결과에 따라 휴식 또는 재도전 안내 문구 제공

### 접근성 방향
- 색상만으로 상태를 표현하지 않고 텍스트 상태를 함께 표시
- 시작/재시작/중단 키를 모든 주요 화면에 안내
- Calibration에서 입력 준비 상태를 뱃지와 텍스트로 동시 표시

## Plan 07. 연동 대비 및 QA

### 입력 구조
- `IMotionInputSource`를 공통 입력 인터페이스로 유지
- `DebugMotionInputSource`와 `WebSocketMotionInputSource`를 교체 가능한 구조로 구성
- `AppRuntime.UseDebugInput()`과 `UseWebSocketInput()`으로 런타임 전환 가능

### 현재 입력 전환 방법
- Title 화면에서 `F1` : 디버그 입력
- Title 화면에서 `F2` : WebSocket 입력

### WebSocket 메시지 예시
```json
{
  "type": "motion_result",
  "motion": "raise_both_hands",
  "confidence": 0.92,
  "timestamp": 1722052800.25,
  "status": "MediaPipe tracking OK"
}
```

### 동작 매핑
- `raise_both_hands` -> `RaiseBothHands`
- `reach_left` -> `ReachLeft`
- `reach_right` -> `ReachRight`

### QA 메모
- 1920 x 1080 해상도 기준으로 패널과 HUD가 중앙에 유지되는지 확인
- Orthographic 카메라 기준에서 UI가 과도하게 잘리지 않는지 확인
- 디버그 입력으로 Calibration 완료 후 Gameplay, Result까지 흐름 확인
- WebSocket 연결 실패 시 상태 메시지가 화면에 보이는지 확인
